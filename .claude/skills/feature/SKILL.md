# Feature Development

## 核心原则

先理解，再设计，最后修改。

## 流程

1. 理解需求。
2. 定位相关代码。
3. 分析现有实现和项目已有模式。
4. 设计最小改动方案。
5. 将方案告诉用户。
6. 如果存在影响实现的设计细节且需求没有明确说明，先询问用户，不要自行决定。
7. 方案明确后再修改代码。
8. 修改完成后检查相关代码和潜在影响。

## 修改原则

- 优先复用现有实现。
- 尽量保持现有架构。
- 只修改必要文件。
- 不进行与需求无关的重构。
- 不随意引入新的依赖。
- 遵循项目已有代码风格。

## Token

- 优先搜索定位，不要盲目读取大量文件。
- 只读取与当前任务相关的代码。
- 已经获得的信息不要重复读取。
- 不要反复解释已经明确的信息。
